## 1. Relational Hierarchy & Authoritative Entity Relationships

The relational architecture strictly preserves the 12 canonical tables:

```
users
 ├── user_profiles (1:1)
 ├── meters (1:N)
 │    └── water_usage_data (1:N)
 │         ├── predictions (1:N)
 │         ├── anomalies (1:N)
 │         └── alerts (1:N)
 ├── consumption_categories (1:N)
 ├── recommendations (1:N)
 ├── goals (1:N)
 ├── feedback (1:N)
 └── chatbot_conversations (1:N)
```

## 2. Source Schema vs. PostgreSQL Translation Matrix

The source documentation contained legacy MySQL syntactic references. To ensure production robustness and relational integrity in PostgreSQL without altering any business logic or table names, the following standard dialect translations were implemented in [`4_DEVELOPMENT/backend/database/init_schema.sql`](file:///c:/Users/singh/Cisco%20Packet%20Tracer%209.0.0/saves/ai%20sustainability%20project/4_DEVELOPMENT/backend/database/init_schema.sql):

| Database Concept | Legacy MySQL Reference | Production PostgreSQL Implementation | Rationale |
| :--- | :--- | :--- | :--- |
| **Primary Keys** | `INT AUTO_INCREMENT` | `INTEGER GENERATED BY DEFAULT AS IDENTITY PRIMARY KEY` / `BIGINT GENERATED BY DEFAULT AS IDENTITY PRIMARY KEY` | SQL standard compliant identity generation in modern PostgreSQL (10+). |
| **Enumerations** | `ENUM('household', ...)` | Standard `VARCHAR(50)` with explicit `CHECK (user_type IN (...))` constraints | Provides identical enum validation behavior with easier schema migration and cross-engine testing. |
| **Timestamps** | `DATETIME` | `TIMESTAMP WITH TIME ZONE` (`TIMESTAMPTZ`) | Accurate global and regional timezone handling for AMI meter reads. |
| **Auto-Updating Times** | `ON UPDATE CURRENT_TIMESTAMP` | Managed via application ORM / transactional update triggers | Standard PostgreSQL convention ensuring explicit audit logging. |
| **Numeric Precision** | `DECIMAL(10,3)` | `NUMERIC(10,3)`, `NUMERIC(12,3)` | Arbitrary-precision exact arithmetic for liquid volume measurements. |

## 3. Catalog of the 12 Authoritative Tables

### 1. `users`
- Primary Key: `user_id` (`INTEGER GENERATED BY DEFAULT AS IDENTITY`)
- Fields: `email` (UNIQUE), `password_hash`, `first_name`, `last_name`, `user_type` (`household`, `institution`, `municipal`), `city`, `country`, `created_at`, `updated_at`, `is_active`.

### 2. `meters`
- Primary Key: `meter_id` (`INTEGER GENERATED BY DEFAULT AS IDENTITY`)
- Foreign Key: `user_id` $\rightarrow$ `users(user_id)` ON DELETE CASCADE
- Fields: `meter_serial_number` (UNIQUE), `meter_type` (`smart`, `digital`, `analog`), `installation_date`, `manufacturer`, `api_key`, `api_endpoint`, `location_description`, `is_active`, `created_at`.

### 3. `user_profiles`
- Primary Key: `profile_id` (`INTEGER GENERATED BY DEFAULT AS IDENTITY`)
- Foreign Key: `user_id` (UNIQUE) $\rightarrow$ `users(user_id)` ON DELETE CASCADE
- Fields: `household_size`, `property_type` (`apartment`, `house`, `commercial`), `property_area_sqm`, `has_garden`, `has_swimming_pool`, `water_source` (`municipal`, `groundwater`, `mixed`), `annual_income_range`, `occupancy_type` (`full-time`, `part-time`, `seasonal`), `conservation_priority` (`high`, `medium`, `low`), `preferred_communication_language`, `privacy_level`.

### 4. `water_usage_data`
- Primary Key: `reading_id` (`BIGINT GENERATED BY DEFAULT AS IDENTITY`)
- Foreign Keys: `meter_id` $\rightarrow$ `meters(meter_id)` ON DELETE CASCADE, `user_id` $\rightarrow$ `users(user_id)` ON DELETE CASCADE
- Fields: `timestamp` (`TIMESTAMPTZ`), `cumulative_reading`, `hourly_consumption_liters`, `daily_consumption_liters`, `monthly_consumption_liters`, `temperature_celsius`, `quality_score` (0–100), `data_source` (`api`, `manual`, `estimated`), `is_validated`, `created_at`.
- Unique Constraint: `(meter_id, timestamp)` prevents duplicate interval readings.

### 5. `consumption_categories`
- Primary Key: `category_id` (`INTEGER GENERATED BY DEFAULT AS IDENTITY`)
- Foreign Key: `user_id` $\rightarrow$ `users(user_id)` ON DELETE CASCADE
- Fields: `category_name` (`bathroom`, `kitchen`, `laundry`, `garden`, `cleaning`, `other`), `date`, `estimated_liters`, `percentage_of_daily`, `estimation_method`.

### 6. `predictions` *(For Phase 3 Integration)*
- Primary Key: `prediction_id` (`BIGINT GENERATED BY DEFAULT AS IDENTITY`)
- Foreign Keys: `meter_id` $\rightarrow$ `meters(meter_id)` ON DELETE CASCADE, `user_id` $\rightarrow$ `users(user_id)` ON DELETE CASCADE
- Fields: `prediction_date`, `predicted_daily_liters`, `predicted_weekly_liters`, `predicted_monthly_liters`, `confidence_score`, `model_version`, `prediction_timestamp`.

### 7. `anomalies` *(For Phase 3 Integration)*
- Primary Key: `anomaly_id` (`BIGINT GENERATED BY DEFAULT AS IDENTITY`)
- Foreign Keys: `meter_id` $\rightarrow$ `meters(meter_id)` ON DELETE CASCADE, `user_id` $\rightarrow$ `users(user_id)` ON DELETE CASCADE
- Fields: `detection_timestamp`, `anomaly_type` (`leak`, `surge`, `low`, `unusual_pattern`), `consumption_value`, `expected_value`, `deviation_percentage`, `severity` (`critical`, `high`, `medium`, `low`), `leak_probability_score`, `alert_sent`, `alert_timestamp`, `user_acknowledged`, `resolution_status` (`pending`, `investigating`, `resolved`, `false_alarm`).

### 8. `recommendations`
- Primary Key: `recommendation_id` (`INTEGER GENERATED BY DEFAULT AS IDENTITY`)
- Foreign Key: `user_id` $\rightarrow$ `users(user_id)` ON DELETE CASCADE
- Fields: `recommendation_type`, `title`, `description`, `estimated_savings_liters`, `estimated_savings_amount`, `priority` (`critical`, `high`, `medium`, `low`), `implementation_difficulty` (`easy`, `medium`, `hard`), `generated_timestamp`, `is_active`, `user_action` (`none`, `viewed`, `in_progress`, `completed`, `dismissed`), `action_timestamp`, `feedback_score`.

### 9. `alerts`
- Primary Key: `alert_id` (`BIGINT GENERATED BY DEFAULT AS IDENTITY`)
- Foreign Key: `user_id` $\rightarrow$ `users(user_id)` ON DELETE CASCADE
- Fields: `alert_type`, `title`, `message`, `related_id`, `related_type`, `severity` (`critical`, `high`, `medium`, `low`), `created_timestamp`, `is_read`, `read_timestamp`, `action_url`.

### 10. `goals`
- Primary Key: `goal_id` (`INTEGER GENERATED BY DEFAULT AS IDENTITY`)
- Foreign Key: `user_id` $\rightarrow$ `users(user_id)` ON DELETE CASCADE
- Fields: `goal_type` (`daily_limit`, `weekly_target`, `savings_amount`, `percentage_reduction`), `target_value`, `target_unit`, `start_date`, `end_date`, `progress_percentage`, `status` (`active`, `achieved`, `missed`, `cancelled`), `created_at`, `updated_at`.

### 11. `feedback`
- Primary Key: `feedback_id` (`INTEGER GENERATED BY DEFAULT AS IDENTITY`)
- Foreign Key: `user_id` $\rightarrow$ `users(user_id)` ON DELETE CASCADE
- Fields: `feedback_type`, `rating` (1–5), `comment`, `response_or_suggestion`, `is_actionable`, `status` (`submitted`, `under_review`, `resolved`, `closed`), `created_timestamp`, `resolved_timestamp`.

### 12. `chatbot_conversations`
- Primary Key: `conversation_id` (`BIGINT GENERATED BY DEFAULT AS IDENTITY`)
- Foreign Key: `user_id` $\rightarrow$ `users(user_id)` ON DELETE CASCADE
- Fields: `session_id`, `turn_number`, `user_message`, `chatbot_response`, `intent_detected`, `confidence_score`, `timestamp`, `was_helpful`.

## 4. Production Indexing
The following high-priority indexes are declared in `init_schema.sql` and verified by test suites:
- `idx_users_email` ON `users(email)`
- `idx_water_usage_meter_time` ON `water_usage_data(meter_id, timestamp)`
- `idx_water_usage_user_time` ON `water_usage_data(user_id, timestamp)`
- `idx_water_usage_timestamp` ON `water_usage_data(timestamp)`
- `idx_anomalies_meter_time` ON `anomalies(meter_id, detection_timestamp)`
- `idx_anomalies_severity` ON `anomalies(severity)`
- `idx_recommendations_user_time` ON `recommendations(user_id, generated_timestamp)`
- `idx_recommendations_priority` ON `recommendations(priority)`
- `idx_alerts_user_read` ON `alerts(user_id, is_read)`
- `idx_alerts_created_time` ON `alerts(created_timestamp)`
- `idx_goals_user_status` ON `goals(user_id, status)`
- `idx_chatbot_user_session` ON `chatbot_conversations(user_id, session_id)`
- `idx_chatbot_timestamp` ON `chatbot_conversations(timestamp)`
